# Бот глазами пользователя

Экраны, кнопки и сообщения бота. Правила расчёта — [`RULES.md`](RULES.md),
устройство — [`ARCHITECTURE.md`](ARCHITECTURE.md), эксплуатация —
[`OPERATIONS.md`](OPERATIONS.md). Примеры имён и чатов вымышлены: бот работает
у бухгалтерской компании «Баланс».

## 0. Принципы

1. **В клиентские чаты бот ничего не пишет.** Только читает. Исключение — служебная
   группа уведомлений из `NOTIFY_GROUP_CHAT_ID`: туда уходят алерты и отчёты, диалога
   там бот не ведёт.
2. **Всё управление — кнопками в личном диалоге.** Текст вводится только там, где
   без него никак: даты, время, имя сотрудника.
3. **Меню собирается по правам.** Пользователь не видит разделов, которых ему нельзя.
4. **Без разработчика.** Чаты, люди, пороги, календарь, рассылки меняются кнопками.
   В конфигурации сервера остаются только секреты, адреса и границы версий правил движка.

Код экранов — `app/bot/handlers/`, кнопки — `app/bot/keyboards.py`, тексты справки —
`app/services/help_text.py`.

## 1. Вход и роли

**Команды** (только в личке): `/start` и `/menu` — главное меню. В группах команд нет.

**Кто что получает на `/start`:**

- активная учётка — приветствие с ролью и главное меню;
- незнакомый человек — нейтральная фраза «Здравствуйте. Этот бот не ведёт переписку.»
  и заявка в очередь. Тем, кто управляет пользователями, приходит «🔔 Новая заявка
  на доступ». Фраза намеренно не упоминает систему доступа: бота видно в клиентских
  чатах, и `/start` может нажать клиент;
- ожидающий или отключённый — та же нейтральная фраза;
- Telegram ID из `BOOTSTRAP_OWNER_TG_ID` при первом входе — сразу владелец.

**Приглашение** — ссылка `https://t.me/<бот>?start=<код>`, одноразовая, на 48 часов,
с ролью «Администратор» или «Сотрудник». **Заявка** — владелец открывает
«🛡 Пользователи бота» → «📥 Заявки на доступ» и выдаёт роль кнопкой. После роли
«Сотрудник» сразу предлагается привязка к записи в справочнике: без неё бот не знает,
чьи показатели показывать.

**Роли:**

| Роль | Что может |
|---|---|
| Владелец | всё, включая передачу владения и назначение совладельца |
| Администратор | всё, кроме передачи владения |
| Сотрудник | «Мои показатели» и свои алерты «нет ответа специалиста» |

Владелец в системе есть всегда: последнего нельзя понизить или отключить, роль можно
только передать (прежний владелец становится администратором). Отдельному пользователю
можно добавить или убрать права поверх роли (в базе, поле `bot_user.permissions`).

Нажатие без прав — всплывающее «Недостаточно прав». Ошибка обработчика на нажатие
кнопки — всплывающее «Действие сейчас не выполнилось. Попробуйте ещё раз или откройте
свежее меню: /menu». На команду или введённый текст при ошибке бот не отвечает ничего.

## 2. Главное меню

| Кнопка | Кому видна |
|---|---|
| 📊 Отчёты | всем, у кого есть хотя бы свои показатели |
| 💬 Чаты | управление чатами (владелец, администратор) |
| 👥 Сотрудники | управление справочником (владелец, администратор) |
| 🛡 Пользователи бота | управление пользователями (владелец, администратор) |
| ⚙️ Настройки | владелец, администратор |
| 🩺 Состояние системы | владелец, администратор |
| 📖 Справка | всем активным |

## 3. 📊 Отчёты

**Разрезы:**

- «📈 Сводный по всем чатам»;
- «💬 По чату» — список чатов в анализе, по 8 на странице;
- «👤 По сотруднику» — список сотрудников, внизу «⏱ Скорость по всем сотрудникам»
  и «🌙 Работа вне графика»;
- «🙋 Мои показатели» — для роли «Сотрудник»; без привязки к справочнику бот объясняет,
  где её сделать;
- «🔥 Требует внимания (сейчас)» — три группы: 🔴 срок вышел, никто не ответил;
  🟡 после реакции ждут ответа; 🟢 новые, в пределах срока. Под списком кнопки чатов
  и «🔄 Обновить»;
- «🕐 Когда пишут клиенты» — распределение по часам и дням недели;
- «🧾 Сводка по алертам» — та же сводка, что по расписанию, но сейчас;
- «✋ Снятые нарушения» — журнал решений «не нарушение»: кто снял, когда, что
  с обращением сейчас.

**Периоды:** «Сегодня», «Вчера», «Последние 7 дней (по вчера)», «Прошлая неделя (пн–вс)»,
«Этот месяц», «Прошлый месяц», «📅 Произвольный период». Произвольный вводится текстом:
`01.08–15.08`, `05.08`, `01.08.2026 – 15.08.2026`, обе даты включительно.
Скользящий и календарный периоды подписаны по-разному намеренно: иначе числа
«7 дней» и «прошлая неделя» не сходятся, и кажется, что бот считает неправильно.
У «⏱ Скорость по всем сотрудникам», «🕐 Когда пишут клиенты» и «🌙 Работа вне графика»
периодов только три — «Сегодня», «Последние 7 дней (по вчера)», «Этот месяц».

**Сводный отчёт:** чаты и сообщения (от клиентов и от компании), нагрузка по чатам,
сотрудники с долей просрочек, блок скорости в рабочем времени — обращений всего,
требовали ответа, отвечено, ждут, остались без ответа; «👤 Менеджеры — первая реакция»
и «🛠 Специалисты — ответ после передачи»: порог, обычное время (медиана),
«9 из 10 — быстрее, чем…», просрочки. Внизу — сколько исходящих без определённого
автора. Длинные списки сокращаются со ссылкой на HTML-файл.

**Отчёт по чату:** входящие и исходящие с числом символов, кто отвечал.
**Отчёт по сотруднику:** сообщения, чаты, активные дни, кто реагировал первым и кто
отвечал по существу, опоздания, разбивка по чатам.

**Кнопки под отчётом:**

- «📥 XLSX», «📥 CSV» — выгрузка (листы «Чаты» и «Сотрудники»);
- «📄 HTML» — у сводного: автономная страница без внешних запросов (главное за период,
  скорость по двум ступеням с раскрывающейся детализацией просрочек, сотрудники,
  проблемные чаты, когда пишут клиенты, работа вне графика);
- провалы в списки обращений (если число больше нуля): «⌛ Ответа так и нет»,
  «⚠️ Ответили с опозданием», «⚠️ Специалист ответил с опозданием», «⏳ Ждут ответа
  специалиста», «❓ Остались без ответа». Кнопка обращения открывает переписку.

## 4. Переписка, решение «не нарушение», «Кто это?»

**«💬 Показать переписку»** — под алертом, в провалах отчётов и в сводке по алертам.
Показывает 3 сообщения до обращения и 15 после, обращение помечено ▶️. Все стороны
подписаны: 🔵 клиент, 🟢 компания с именем сотрудника, ⚙️ система (служебные ответы
Bitrix24), ⚪ не определено. Кнопки «‹ Раньше» / «Позже ›», «👥 Участники»,
«✖️ Закрыть переписку».

Пример выписки из чата «Бухгалтерия: ООО Ромашка»:

```
— сегодня —
10:02 🔵 клиент 1: Пришлите, пожалуйста, акт сверки за квартал
▶️ 10:15 🔵 клиент 2: И подскажите, когда будет готова декларация?
10:21 🟢 Ирина Соколова: Добрый день! Акт пришлю сегодня, по декларации уточню у специалиста
16:40 🟢 Дарья Лебедева: Декларация будет готова в четверг
```

**«Клиент 1», «Клиент 2».** Если со стороны клиента в чате пишут двое и больше, они
подписаны номерами. Номер даётся по первому сообщению человека в чате, поэтому один
и тот же человек везде под одним номером — в алерте, в выписке и в «Участниках».
Если человек со стороны клиента в чате один, номера нет — просто «клиент».

**Снятие нарушения** (владелец, администратор): «✔️ Снять нарушение» → подтверждение
«✅ Да, снять» или «✖️ Нет, оставить». Обращение уходит из списков нарушений, счётчиков
просрочек и «ждут ответа», алерт по нему зачёркивается как «закрыто вручную». Само
обращение и его время не меняются. Вернуть — «↩︎ Вернуть нарушение». Все решения
видны в отчёте «✋ Снятые нарушения».

**«👥 Участники»** — кто писал в видимом куске переписки и сколько раз (люди клиента —
с тем же номером, что в выписке). У каждого — карточка **«Кто это?»**: текущая сторона
(🔵 клиент, 🟢 компания, ⚙️ система, ⚪ не определено) и почему, в каких чатах писал,
последнее сообщение. Действия (владелец, администратор):

- «👤 Сотрудник ›» — выбрать роль, затем человека из справочника;
- «🔵 Клиент»;
- «⚙️ Система / бот» — за отправителем нет человека, его сообщения не учитываются
  ни за кого;
- «↩️ Сбросить решение» — вернуть автоматическое определение;
- «✅ Да, это <имя>» — если бот нашёл подсказку в служебном ответе Bitrix24
  об авторизации.

Решение действует на отправителя целиком: на всю его прошлую и будущую переписку.
Для «анонимного админа» (сообщения «от имени группы») решение действует только
в этом чате: за служебной учёткой Telegram в каждом чате стоит свой человек.

## 5. 💬 Чаты

Состояния: «🆕 обнаружен», «✅ в анализе», «⏸ на паузе», «📦 в архиве».

- Главный экран: кнопки состояний с числом чатов, «✅ Включить все обнаруженные (N)»,
  «🔍 Найти чат» (по части названия, например «Ромашка»).
- Карточка чата: состояние, сколько сообщений собрано, «В анализе с», пометка о темах
  форума. Кнопки «✅ Включить в анализ», «⏸ Поставить на паузу», «📦 Убрать в архив»,
  «🗑 Удалить чат» (только из архива, с подтверждением, необратимо).
- Добавили бота в группу — чат сразу в анализе (если в настройках не выключено
  автовключение; тогда он ждёт в «обнаруженных»). Удалили бота — чат уходит в архив,
  история сохраняется. Вернули — снова в анализе.
- Пауза и архив выключают алерты по чату. Отчёт за прошлый период учитывает только
  время, когда чат был в анализе.

## 6. 👥 Сотрудники

- Главный экран: «🎓 Специалисты — N», «🤝 Менеджеры — N», «❓ Роль пока не определена — N»,
  «➕ Добавить сотрудника», «🔍 Не определили, кто это — N», «🤖 Не сотрудники — N».
- Справочник наполняется сам из подписей интегратора. Вручную добавляют «Имя Фамилия»;
  однофамильца отличают припиской через запятую. После добавления старые сообщения
  размечаются заново.
- Карточка сотрудника: «✏️ Роль» — «🎓 Специалист», «🤝 Менеджер» или «🤖 Определять
  автоматически» (роль ставится по наблюдаемым передачам, после двух сигналов);
  «✍️ Добавить написание имени»; «🚪 Больше не работает» / «↩︎ Вернуть в работу».
- **Очередь «Не определили, кто это»**: незнакомые подписи интегратора и чужие боты.
  Для подписи — выбрать роль и человека, «🚫 Это не сотрудник», «💬 Показать переписку»,
  «Пропустить ›». Для бота — карточка «Кто это?». Помеченные «не сотрудник» лежат
  в «🤖 Не сотрудники», оттуда их можно вернуть в очередь.

## 7. 🛡 Пользователи бота

- Список: всего, активных, отключённых (⛔), ждут подтверждения. Кнопки
  «📥 Заявки на доступ — N», «🎟 Создать приглашение» (роль «Администратор» или
  «Сотрудник», затем «📋 Скопировать ссылку»).
- Карточка: роль, состояние, уведомления в личку, Telegram ID. Кнопки
  «Сделать: Администратор» / «Сделать: Сотрудник», «👑 Сделать совладельцем»
  и «👑 Передать владение» (только владельцу, с подтверждением), «🔗 Привязать
  к сотруднику» (список или «🔎 Найти по имени», «✖️ Снять привязку», «⏭ Пока без
  привязки»), «⛔ Отключить» (у отключённого вместо неё — «✅ Включить»: доступ
  возвращается с прежней ролью), «🔔 Уведомления в личные сообщения: да/нет».
- Выключить уведомления в личку можно, только если алерты и рассылки уже идут
  в группу уведомлений.
- Один сотрудник привязывается только к одной учётке. После привязки прямые сообщения
  этого аккаунта в чатах считаются сообщениями компании.

## 8. ⚙️ Настройки

Разделы с полями; да/нет и варианты меняются кнопками, числа и время — вводом
с проверкой. Значения по умолчанию — [`RULES.md`](RULES.md), раздел 12.

- **🕐 Рабочий календарь** — рабочие дни (1 = пн … 7 = вс), начало и конец дня,
  часовой пояс, праздники.
- **🔔 Алерты** — порог первой реакции (мин), срок ответа специалиста после передачи
  (1440 = то же время следующего рабочего дня), «Алерты «нет ответа специалиста»»,
  «Алерты в группу уведомлений», «Уведомления только в рабочее время», «Отправка
  алертов» — общий выключатель.
- **📈 Обращения** — сколько ждать реакции после просрочки (часов), сколько ждать
  специалиста после просрочки (дней); потом обращение закрывается как «осталось
  без ответа». «Макс. сообщений в обращении».
- **📮 Отчёты по расписанию** — блоки «1️⃣ Вечерняя сводка», «7️⃣ Недельный отчёт»,
  «3️⃣0️⃣ Месячный отчёт», «🧾 Сводки по алертам» (1–5 времён в день), «📤 Общее
  для отчётов» (состав полный или краткий, «Слать и в группу уведомлений»).
  Включение рассылки не досылает прошлый выпуск.
- **🗄 Хранение** — сколько дней хранить сырые апдейты и тексты сообщений
  (тексты по умолчанию бессрочно).

**Версии настроек.** Календарь, пороги и окна ожидания хранят историю. Под полем
видны прошлые версии, кнопка «🕐 Действует с …» задаёт момент вступления
(`ДД.ММ ЧЧ:ММ`, «сейчас», «с начала дня»; не в будущем и не раньше предыдущей версии).
Обращение считается по настройкам на момент открытия, поэтому правка не переписывает
прошлые отчёты.

## 9. 🩺 Состояние системы

- Окружение и версия сборки (sha коммита, дата).
- Строка «ИИ»: «включён», «выключен», «работает на резерве (<модель>)» или
  «⚠️ <причина сбоя>», например «⚠️ Истёк или отозван API-ключ провайдера ИИ».
  Расход за месяц (доля от потолка) и по дням в рублях, последний живой контакт
  с провайдером, скорость ответа.
- Очередь разметки, последний вердикт, сообщения без разметки за сутки.
- Пульс фонового обработчика, последнее сообщение из чатов.
- Чаты (всего и в анализе), сотрудники, нераспознанные авторы, получатели алертов,
  пользователи.
- Блок «Неполадки», если что-то не так: не задан ID интегратора, нет чатов в анализе,
  пустой справочник, апдейты с ошибкой, неизвестный бот пишет в чатах (с его ID),
  алерты включены без получателей, ИИ на резерве или сбоит, медленный провайдер,
  расход выше 80 % потолка, недоставленные алерты, worker молчит дольше 5 минут.
  К каждой строке — что делать.
- «📜 Журнал действий» — последние 25 действий людей: роли, чаты, настройки,
  снятия нарушений, разметка.

Кнопок «перезапустить» или «пересчитать» здесь нет: всё, что нужно, система делает сама.

## 10. 📖 Справка

Разделы «🕐 Сроки», «💬 Обращения», «📊 Отчёты», «🔔 Уведомления», «🤖 Распознавание»,
«👥 Доступ и чаты». Тексты подставляют текущие настройки (график, пороги, расписание)
и показывают только то, что доступно читателю. Главная мысль справки: бот следит
за скоростью ответов, статус «отвечено» не подтверждает, что задача выполнена.

## 11. Что бот присылает сам

**Кому.** Алерты и рассылки — в личку владельцам и администраторам с включёнными
уведомлениями в личку, и в группу уведомлений, если это включено в настройках.
В группу уходит только текст, без кнопок. Системные сообщения (сбой ИИ, простой,
заявки) приходят в личку независимо от флага.

**Алерт.** Заголовок «🔴 1 · Нет реакции» или «🟠 2 · Нет ответа специалиста».
В тексте: на сколько просрочено и до какого времени надо было ответить, чат, когда
и что написал клиент («Клиент 2», если людей со стороны клиента несколько), последнее
сообщение клиента, ответила ли компания и кто, календарное ожидание и график.
Кнопка «💬 Показать переписку» — в личке. Сотрудник, передавший вопрос специалисту,
получает свой алерт второго вида без кнопок.

Пример:

```
🔴 1 · Нет реакции
Просрочено на 12 мин — ответить надо было до сегодня в 10:32 (порог 30 мин)

Чат: Бухгалтерия: ООО Вектор

👤 Клиент — сегодня в 10:02
«Пришлите, пожалуйста, счёт на оплату за октябрь»

🏢 Компания не отвечала с момента обращения.

Календарно ждёт 42 мин. График: 10:00–19:00, пн–пт.
```

**Зачёркивание.** Когда обращение закрыто, исходный алерт правится (в течение 48 часов):
заголовок «🟢 … — отработано», «✋ … — закрыто вручную» или «🤖 … — ответа
не требовалось», тело зачёркнуто, внизу — кто ответил и сколько прошло после алерта.
Обращение, оставшееся без ответа, не зачёркивается.

**Сводка по алертам** — по рабочим дням в заданное время («Утренняя», «Дневная»,
«Вечерняя»). Блоки: 🔴 «Нет реакции менеджера», 🟠 «Нет ответа специалиста» — всё,
что горит; ❓ «Остались без ответа»; 🟢 «Закрыто» — каждое закрытие один раз. Пустая
сводка тоже приходит: «Алертов в ожидании ответа нет».

**Вечерняя сводка** «📊 Сводка за ДД.ММ»: по сотрудникам, «❓ Осталось без ответа»,
нарушения по чатам. **Недельный и месячный отчёты** — текст сводного отчёта и вложения
XLSX и/или HTML. Выпавший на выходной отчёт уходит в первый рабочий день.

**Служебные сообщения:**

| Сообщение | Когда |
|---|---|
| «⚠️ ИИ-классификация недоступна» — причина, что делать, «Алерты приостановлены» | 3 неудачных прохода подряд или исчерпан месячный потолок |
| «✅ ИИ-классификация снова работает.» | после восстановления |
| «🐢 Провайдер ИИ отвечает медленнее обычного», напоминание не чаще раза в 3 часа, «✅ …снова отвечает нормально» | медленный провайдер или отстающая очередь |
| «⚠️ Бот не работал …» с границами простоя | старт worker после простоя больше 5 минут |
| «ℹ️ Группа уведомлений переехала» | Telegram перевёл группу в супергруппу |
| «🔗 Появились новые сотрудники в справочнике» | есть учётки «Сотрудник» без привязки |
| «🔔 Новая заявка на доступ» | незнакомец нажал `/start` |
